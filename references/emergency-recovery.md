# 紧急恢复：先恢复控制通道

> 本文件只有两个入口：高风险变更前，`control-channel-safety.md` 只调用下面的离线恢复信息卡；已经失联后，使用紧急避险步骤。普通独立远端变更不需要预先加载整份恢复流程。

恢复阶段先建立一条已知可用的控制通道，联网后再查根因。

## 变更前离线恢复信息卡

只有控制通道门禁判定需要离线恢复材料时，才在首次写入前把恢复信息卡写入用户本机固定路径的纯文本文件，并把路径告诉用户。卡片不含密码、Token、节点链接、UUID、代理凭据或私钥，只保留恢复所需的非秘密外键。

```text
事件时间和目标设备：
原来的正常网络或代理配置：
本次修改对象：
变更摘要或计划 ID：
备份和回执位置：
自动回滚是否已武装、等待多久：
最后一个确认成功的步骤：
服务商控制台或独立网络是否可用：
请勿重复的操作：
```

## 紧急避险卡

1. 停止继续修改，不删除配置、备份、日志、计划或恢复信息卡。
2. 若自动回滚已武装，等待声明时间，不重复执行同一操作。
3. 关闭正在测试且已失效的 TUN 或系统代理，但不要卸载代理软件或删除配置。
4. 切换到不经过故障路径的网络、设备或已验证独立代理。
5. 用浏览器确认普通 HTTPS 可用；需要代理时只启动最后确认可用的独立配置。
6. 重新启动 Agent，把恢复信息卡交给它，从现场状态继续，不凭记忆重做变更。

### macOS

1. 在代理应用中关闭测试中的 TUN 或系统代理开关，保留配置。
2. 在“系统设置 -> 网络 -> 当前网络 -> 详细信息 -> 代理”关闭仍指向失效本地端口的代理。
3. 连接独立网络并验证普通 HTTPS；`scutil --proxy` 只用于只读核对。
4. 网络正常后重新打开 Agent，不先执行全量网络重置。

### Windows

1. 在代理应用中关闭测试 TUN，保留订阅、配置和日志。
2. 在“设置 -> 网络和 Internet -> 代理”关闭仍指向失效本地端口的代理服务器。
3. 连接独立网络，验证普通 HTTPS，再只启动最后确认可用的代理配置。
4. 不把 `netsh winsock reset`、全量路由清空或重装网卡作为第一步。

### Linux 桌面

1. 关闭测试 TUN 和失效的手动系统代理，保留配置和日志。
2. 只在当前终端取消错误的 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY`，不改全局启动文件。
3. 连接独立网络并验证普通 HTTPS，然后重新启动 Agent。
4. 不在远程 SSH 会话中随意重启 NetworkManager、systemd-networkd 或整机网络。

### VPS 或节点已经失联

1. 若自动回滚已武装，等待声明时间，再从独立网络检查 SSH 和旧节点。
2. 仍未恢复时进入变更前已验证的服务商控制台。
3. 检查计划备份目录和 `automatic-rollback.status`，不要凭文件时间猜结果。
4. 只恢复该事务列出的备份并重启受影响服务，然后验证 SSH、面板、旧路径和目标路径。
5. 控制台也不可用时停止高风险尝试，联系服务商并保留磁盘和控制台现场。

## 恢复后

不要把“重启后恢复”当作根因。先确认控制通道、旧路径、目标路径和回滚状态，再决定是否建立新的诊断或变更事务；原事务的授权不自动延续。
