# 对话与执行确认

## 直接行动

目标、范围和授权边界明确时直接处理，不先展示流程菜单。用户要求只分析、只读或只给方案时，停在该边界。

能够通过只读扫描获得的系统、网络、路由、DNS、TUN、地址族和服务事实由 Agent 自己检查，不让用户猜测；已经从本轮或现有上下文得到的信息不重复询问。

## 只在必要时提问

只有缺少的用户选择无法通过安全的只读检查获得，并且会改变目标、范围、费用、外部数据披露、风险或是否写入时才提问。默认一次只问一个问题。

确实需要选择时：

- 用一句话说明已知事实和为什么这个选择会改变下一步。
- 提供 2–3 个互斥选项会更清楚时，推荐项放在第一位，并简述每项的影响；否则直接问一个短问题。
- 结构化工具可用时使用 `request_user_input`、`AskUserQuestion` 或所在 Agent 的等价工具。
- 不让用户判断“是 DNS、MTU、路由还是 TLS”；这是诊断应回答的问题。
- 不把讲解深度、扫描深度或流程阶段做成默认菜单。用户可随时要求更多解释。

必需的授权或选择没有答案时等待，不能把推荐项、沉默或超时当作同意。

## 授权边界

公网查询、精选外部工具、带宽压测、临时抓包和远程写入按各自的数据或副作用分别说明并取得所需授权。一个授权不能替代另一个。

“讨论方案”“选择设计”“完成只读审计”不能代替对最终远程操作的明确授权。远程写入只在准确操作已经确定后，通过下面的唯一最终执行卡确认一次。

## 唯一最终执行卡

每张卡必须有唯一的「执行卡 ID」，并绑定本次操作的完整范围。使用精确计划时同时列出完整计划 ID；直接 SSH 事务则列出确切目标主机、受影响对象和已审核的变更摘要。卡片只展示一次，内容包括：

1. 目标主机、准备新增、修改、删除或重启的对象，以及明确不变的旧节点、面板、SSH、默认路由和无关出口。
2. 预计中断、最坏后果、受影响客户端、备份位置、回滚触发条件和验证方法。
3. 已知残余风险的完整清单和可行的更安全替代路径；没有已知残余风险时明确写「无已知残余风险」，不留空白。

卡片末尾只提供三个互斥选择：

1. `执行并接受本卡列出的残余风险`
2. `只保留方案`
3. `取消`

第一个选择同时是对该执行卡 ID 所绑定准确操作的授权，以及对卡中已列残余风险的逐项接受；它不覆盖卡外操作或未披露风险。没有用户回复时等待，不能把推荐项、沉默或超时当作同意。授权后由 Agent 执行已审核的远端 SSH 事务并验证，不把普通 Linux 命令转交给用户。

授权只对该执行卡 ID 和其完整内容有效。目标主机、计划 ID、受影响对象、变更内容、执行方式、中断影响、备份、回滚、验证或残余风险任一项发生实质变化，原授权立即失效；更新范围后生成新的执行卡 ID 并重新确认。这不是对同一操作重复确认。

共享路径、精确文件事务和残余断线风险按 `control-channel-safety.md` 处理。需要切换本机 TUN、系统代理、活动代理进程、DNS、路由或网络时，每次只给一个主要动作，并说明目的、预期结果、异常处理和撤销方式。
