# 引导式选择规范

## 目的

选择题是为了帮助不熟悉网络术语的用户做决定，不是把配置工作推回给用户。Codex 应先利用现有上下文和只读扫描缩小范围，再询问真正会影响下一步的选择。

## 什么时候提问

出现下面任一情况时再提问：

- 用户的目标可能进入不同工作流。
- 缺少的信息会改变扫描范围、风险、费用或是否修改远程设备。
- 有两个以上合理路径，需要用户决定先后顺序。
- 必须确认设备所有权、外部查询、临时抓包或远程变更边界。

下面这些情况不要提问：

- 当前请求、目标和安全边界已经明确，可以直接执行。
- 系统、网卡、路由、DNS、IPv4/IPv6 等事实能够通过只读扫描获得。
- 用户已经在本轮或现有上下文中回答过同一个问题。
- 只是为了显得流程完整，而答案不会改变下一步。

## 提问格式

- 每轮最多提 3 个问题，优先只提当前最关键的 1 个。
- 每题提供 2–3 个互斥选项；不要一次展示长菜单。
- 推荐项放在第一位，并在标签后写 `（推荐）`。
- 标签保持简短；每个选项用一句话解释接下来会做什么、有什么限制或代价。
- 提问前先用一句话说明已经知道什么、为什么现在需要这个选择。
- 如果 `request_user_input` 等结构化提问工具可用，优先用它显示可点击选项；否则使用编号列表。
- 结构化界面会自动提供“其他”时，不重复添加；普通文本中允许用户直接补充自己的情况。

普通文本示例：

```text
目前还不知道问题在客户端还是服务器，先选一个观察范围：

1. 当前设备（推荐）：先做本机只读扫描，不会连接或修改 VPS。
2. VPS：检查服务、监听、路由和资源，需要确认 SSH 授权。
3. 节点全链路：同时收集客户端、VPS 和目标站证据，耗时更长但归因更完整。
```

## 解释方式

- 第一次出现术语时立刻解释，例如“入站是流量进入 VPS 的方式”。
- 先说明选项对用户有什么影响，再补充协议或内核细节。
- 用户选择后，复述选择及其边界，然后开始执行或提出下一个必要问题。
- 不要求用户判断“是 DNS、MTU 还是路由问题”；这是扫描和诊断应回答的事情。
- 不确定的事实显示“未知”，不要用选项诱导用户猜测。

## 安全与授权

- “只读扫描”“生成计划”“审核并交接”可以作为流程选择。
- 本版本的“审核并交接”只会形成计划和人工操作边界，不会调用远程执行或回滚入口。
- 该选择不能代替对最终计划 ID 的明确授权；即使已经授权，本版本仍停在交接阶段。
- 公网出口查询、精选外部工具、带宽压测、临时抓包和远程写入分别说明数据影响，并分别取得所需授权。
- 外部查询授权只允许已说明的网络请求：节点工具和公网出口查询使用 `--external`，客户端/本机服务器工具使用独立的 `--tool-external`；两者都不能代替 iperf3 的 `--allow-load`，也不能代替远程变更授权。
- 选项中不展示或索取密码、私钥、节点链接、UUID、代理凭据和 API Token。
- 必需的授权问题没有答案时必须等待；不能用推荐项或超时默认代替授权。

## 什么时候直接行动

- 明确的本地只读扫描：直接扫描，再用结果提供下一步选择。
- 明确的术语问题：先回答，再询问是否要结合当前环境检查。
- 明确且已授权的变更：生成并审核计划后停止；本版本不执行远程写入，授权也不能绕过该发布门禁。
- 用户明确要求只分析或只给方案：停在对应边界，不借菜单扩大操作范围。

## 两组常用选择

目标不明确时：

1. `先只读检查（推荐）`：收集环境事实，不修改设备。
2. `排查当前故障`：围绕正在发生或曾经发生的问题收集证据。
3. `搭建或修改`：先审计现状并生成变更计划。

用户想控制讲解深度时：

1. `边做边解释（推荐）`：每一步只解释当前需要理解的内容。
2. `先看结论`：先给结果和下一步，需要时再展开。
3. `深入原理`：补充协议、路由和系统层面的技术解释。

内置检查无法回答下一步时：

1. `继续基础扫描（推荐）`：不安装新工具，先使用现有证据。
2. `运行一个专项工具`：说明工具、目标、发送的数据和限制后，只运行最匹配的一个。
3. `审核后安装工具`：先核对官方来源、稳定版本或提交和校验和，再等待安装授权。

检测到 Codex 可能依赖待修改网络时：

1. `切换独立通道（推荐）`：先用独立网络、代理进程或设备验证 Codex 仍可连接，再修改目标路径。
2. `生成回滚审核合同`：只把目标、备份和恢复要求写入计划，不会武装 timer 或执行远端写入。
3. `人工维护窗口`：工具执行保持阻止；Codex 只提供逐步审核材料，用户需要一直在设备旁并使用独立获批流程。

用户选择人工维护窗口后，每次只给一个主要动作，并按 `control-channel-safety.md` 同时说明目的、预期结果、异常处理和撤销方式。这个选择不能代替独立通道，也不能让本版本未发布的执行器变成可用。
