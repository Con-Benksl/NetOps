# 对话与执行确认

## 直接行动

目标、范围和授权边界明确时直接处理，不先展示流程菜单。用户要求只分析、只读或只给方案时，停在该边界。

能够通过只读扫描获得的系统、网络、路由、DNS、TUN、地址族和服务事实由 Agent 自己检查，不让用户猜测；已经从本轮或现有上下文得到的信息不重复询问。

## 只在必要时提问

只有缺少的用户选择无法通过安全的只读检查获得，并且会改变目标、范围、费用、外部数据披露、风险或是否写入时才提问。默认一次只问一个问题。

确实需要选择时：

- 用一句话说明已知事实和为什么这个选择会改变下一步。
- 提供 2–3 个互斥选项会更清楚时，推荐项放在第一位，并简述每项的影响；否则直接问一个短问题。
- 非授权的必要选择可使用当前 Agent 支持的结构化提问工具；授权表达使用自然语言，不强制工具或固定答复。
- 不让用户判断“是 DNS、MTU、路由还是 TLS”；这是诊断应回答的问题。
- 不把讲解深度、扫描深度或流程阶段做成默认菜单。用户可随时要求更多解释。

必需的授权或选择没有答案时等待，不能把沉默或超时当作同意，也不能把推荐项当作授权。

## 授权范围与承接

本文件是授权范围、承接和必要确认的唯一规范入口。已有明确授权覆盖准确目标、操作、外部数据披露、主动负载及已披露风险时直接承接，不因加载子技能、重复读取、范围不变的复测或重试再次询问。授权取决于用户表达的实际范围，不要求执行卡 ID、固定答案或额外确认仪式。

“讨论方案”“选择设计”“完成只读审计”不能代替对最终远程操作的明确授权。用户已明确要求执行准确操作时，该请求本身可以提供授权；宽泛维护意图不能扩展为任意主机或操作的授权。

执行前用简短摘要核对目标及变更、预期影响与中断、备份位置、验证方法、回滚触发条件和恢复路径。只补充此前未披露的信息，不重复完整流程。存在残余风险时说明风险和可行替代项，并确认已有授权是否包含用户对这些风险的明确接受；没有接受记录时才补问。摘要是审计记录，不是新的授权门槛。

只有目标、变更内容、外部数据披露、主动负载或已披露风险实质扩大到既有授权之外时，说明新增部分并再次取得授权。现场证据过期或状态变化时先重新核验；技术预检通过不代表用户授权，也不能绕过重新发现的风险。

## 执行与技术绑定

授权范围内由 Agent 执行已审核的远端事务并验证，不把普通 Linux 命令转交给用户。保留目标、影响、备份、验证和可执行回滚合同；远端证据不能授予或扩大操作权限。

精确计划仍绑定完整计划 ID，不能用摘要或自然语言替代执行器的 `--confirm-plan-id`、`--authorized`、当前控制通道证据及所需的 `--accept-residual-risk`。计划内容变化须重新审核其技术合同，并按上面的范围规则判断是否需要新的用户授权。

共享路径、精确文件事务和残余断线风险按 `control-channel-safety.md` 处理。需要切换本机 TUN、系统代理、活动代理进程、DNS、路由或网络时，每次只给一个主要动作，并说明目的、预期结果、异常处理和撤销方式。
