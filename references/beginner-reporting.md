# 对话输出与导出

## 默认输出

不要自动创建专门的中文报告或 Markdown 文件。

- 纯问答、术语解释和方案讨论：只在对话中回答，不生成 JSON 或报告文件。
- 正式扫描：只把机器可读 JSON 保存到用户指定或工具约定的位置；不自动生成同名 Markdown。
- Agent 在对话中概括四项：结论、关键证据、限制、下一步。内容可以合并成自然段，不要求固定标题或固定篇幅。
- 只有用户明确要求导出时，才生成其指定格式的报告。变更事务自身必需的计划、回执和回滚状态仍按安全合同保存，它们不是面向用户的固定扫描报告。

## 表达边界

先说结论和当前最有用的动作，再补充必要解释。第一次出现缩写时给出中文含义；使用“可观测路径”而不是“真实完整线路”。

只陈述证据支持的最小范围：

- 证据充分时说明决定性观察及时间。
- 仍有关键观察点缺失时明确说“未知”或“目前证据更支持”，不要把单次 traceroute、第三方 IP 标签、无响应或重启后恢复写成确定根因。
- 下一步已经明确时直接推荐，不为了互动强制展示菜单；只有缺少会改变动作的用户选择时才按 `guided-dialogue.md` 提问。
- 下一步涉及网络写入时，先按 `control-channel-safety.md` 完成控制通道判断和一次最终确认。
