# 可观测传输路径

## 分段模型

```text
客户端
  -> 本地网卡和默认路由
  -> 接入网络与运营商路径
  -> VPS 公网入口
  -> 防火墙与入站监听
  -> Xray 路由和出站
  -> 可选上游 SOCKS/HTTP 代理
  -> 目标站
```

每项观察必须记录时间、观察点、目标、地址族和协议。TCP 443 的路径不能自动代表 UDP 节点或其他目标端口。

## 能直接观察

- 客户端和 VPS 自己的接口、路由表、DNS 配置、监听、进程和本机连接结果。
- 从每个可控观察点发起的 DNS、TCP、TLS、HTTP 和有限 traceroute 结果。
- Xray 配置中声明的入站、路由标签和出站，以及端到端请求得到的最终出口。
- 同一条件下两个诊断包之间的差异。

## 通常不能直接观察

- 运营商内部不响应探测的设备和 MPLS 标签背后的实际转发。
- 去程与回程是否完全一致。
- 上游代理接收连接后在其内部选择的完整路径。
- 目标站未公开的 WAF、风控和账号决策。
- 被代理接管后，本机公网查询究竟代表直连还是代理，除非明确控制测试路径。

## 解释规则

- 中间一跳不响应、后续跳正常：不得判定该跳故障。
- traceroute 与应用连接目标或协议不同：只能作为旁证。
- 单个 ASN/IP 数据库标签：只能描述该数据源的分类。
- 入口正常、指定出口失败：将范围缩小到代理路由、上游和目标段，不要回头猜本地 Wi-Fi。
- 两台设备同时失败：先寻找共享节点、DNS、出口或目标，再比较各自本地路径。
