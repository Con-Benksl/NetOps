# 多设备间歇性超时

## 参数化环境

- 客户端：桌面系统 A 与桌面系统 B
- 接入：同一个本地网络
- 节点：共享同一入口和出口

## 用户看到的现象

两台设备在相近时间全部超时，另一节点仍可用。重新导入配置或重启客户端后恢复，过一段时间再次出现。

## 对照测试

对齐两台设备的时间，在同一窗口内比较入口连接、VPS 日志、出站连通性和恢复时刻。再用另一个不共享入口的节点做对照，确认失败是否跟随共享组件。

## 支持和反对每个解释的证据

- 支持「共享组件故障」：两端失败时间重叠；换用不共享入口的节点立即正常；VPS 日志在同一时刻出现异常。
- 支持「本地网络共因」：两端失败时间重叠，但换节点也不恢复，说明共因在本地网络或出口更上游。
- 反对「两台客户端各自损坏」：两台独立设备在同一时刻自发损坏的先验概率极低，除非它们刚共同升级过同一个客户端版本。
- 重启或重新导入后恢复只说明状态被重置，不指向任何具体原因。

## 现有证据能确认的故障范围

能确认「失败与共享组件相关，而非客户端各自损坏」。在拿到故障时段的两端证据之前，不能断定是 CGNAT 映射变化、节点热更新、客户端端口耗尽还是服务器路由。

## 不能从这份案例推广出去的结论

- 不能推广成「多设备同时故障一定是服务器问题」：同一本地网络、同一 DNS、同一客户端版本都是共因。
- 不能推广成「重启能修就是客户端的问题」：状态重置能掩盖服务端的连接表或会话问题。

## 推荐下一步

用 `netopsctl monitor install --dry-run` 审查客户端和 VPS 两端的限时采样设计（本版本不安装任何调度任务），在故障复现窗口手动运行有界重复扫描，并以同一目标和协议复现一次。
