# 分层故障诊断

## 最小对照

每次只改变一个变量：

- 代理关闭与开启；
- IPv4 与 IPv6；
- TCP 与 UDP；
- 域名与固定地址；
- VPS 原生出口与上游出口；
- 客户端 A 与客户端 B；
- 目标 A 与目标 B。

记录同一时间窗口。无法控制其他变量时，不给确定性结论。

任何可能重启代理、切换 TUN 或修改 DNS/路由的对照实验，都先经过 [`control-channel-safety.md`](control-channel-safety.md)。不能用“试着重启一下”换取证据，同时把 Codex 的控制通道切断。

## 故障段

| 区段 | 关键证据 | 常见误判 |
| --- | --- | --- |
| 客户端 | 进程、TUN、路由、DNS、日志 | 重启后恢复就认定服务器故障 |
| 接入网络 | 网关、协议匹配探测、丢包/抖动 | 中间跳不回 ICMP 就认定线路丢包 |
| VPS 入口 | DNS、端口、握手、监听、防火墙 | “连接拒绝”与“超时”混为一谈 |
| 代理内核 | 版本、配置测试、路由标签、资源 | 服务 active 就认为节点端到端正常 |
| 上游出口 | 认证、目标端口、DNS、出口 IP | 把代理商出口当作 VPS 网卡 IP |
| 目标站 | HTTP/TLS 状态、出口对照、账号状态 | 一个站拒绝就认定整个代理不可用 |

## 间歇性问题

- 建立正常基线。
- 使用同一时钟记录客户端、VPS 和目标事件。
- 连续失败触发短时增强采样，保存故障和恢复两个路径快照。
- 将“重启、换端口、重导入后恢复”记录为状态变化，不直接当根因。
